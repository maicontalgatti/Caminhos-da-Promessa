# Checklist editorial de qualidade de missão

Usar **depois** dos gates técnicos da fábrica e **separado** da revisão bíblica/histórica.
Não é nota científica. Cada item: sim / parcial / não + uma frase de evidência.

## Experiência
- [ ] Início compreensível (jogador sabe o que fazer nos primeiros minutos)
- [ ] Motivação clara (problema ou curiosidade, não só “vá falar com X”)
- [ ] Desenvolvimento (a situação evolui; não é lista plana)
- [ ] Conclusão satisfatória (fecho emocional ou cognitivo, sem monólogo eterno)
- [ ] Integra-se ao mundo (NPCs/objetos existem fora do corredor da missão)

## Personagens e diálogo
- [ ] Personagens relevantes têm função distinta
- [ ] Há interação significativa (não só expo dump)
- [ ] Perguntas opcionais existem quando agregam (sem gate artificial)
- [ ] Escolhas, se houver, têm eco (flag/fala/recompensa) ou são honestamente cosméticas

## Gameplay
- [ ] Usa variedade de mecânicas **já existentes** adequada ao tema
- [ ] Evita repetição sem propósito (N× “fale com”)
- [ ] Exploração/atividade corporal quando o tema pede (ex.: água → carregar)
- [ ] Objetivos não são padding para esticar tempo

## Aprendizado bíblico
- [ ] Referências verificáveis (`scripture` / textos importados)
- [ ] Ficção marcada; relato central intacto
- [ ] Descoberta educativa consultável depois (diário)
- [ ] Ensino espalhado o suficiente para não ser só epílogo

## Técnica (aponta para quest-qa)
- [ ] Alvos reais; eventos disparam; save/load ok
- [ ] Sem regressão na suíte

## Veredito de qualidade (não substitui `tested` / `approved`)

- [ ] Precisa de outra passagem de design
